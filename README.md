# QQ 音乐 · 快捷保存

一个 Chrome Manifest V3 扩展：复制 QQ 音乐歌曲链接，点击工具栏图标，自动打开网页、尝试播放、捕获可获取的普通音频，并按“歌名－歌手.mp3”保存。非 MP3 音频在本机真正转码。

当前版本 **0.3.0 预览版**。0.2 的网页捕获与本地 MP3 流程已在 macOS Chrome 真机验证；0.3 的系统文件夹选择、写入授权、记住目录和真实 MP3 直接保存均已在 macOS Chrome 真机验证；Chrome 重启后的再次授权仍待验证。

## 安装

1. 下载项目 ZIP 并解压，或克隆本仓库。
2. Chrome 地址栏输入 `chrome://extensions`，打开“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择项目中的 `extension/` 文件夹（直接包含 manifest.json）。
4. 固定“QQ音乐 · 快捷保存”到工具栏。更新代码后，在扩展管理页点“重新加载”。

需要 Chrome 127 或以上版本。无需运行后台服务，也无需为日常使用安装 Node.js 或 FFmpeg。不要删除或移动已加载的 extension 文件夹。

## 使用

1. 在 QQ 音乐中“分享→复制链接”。也支持直接复制 HTTPS 歌曲详情页链接。
2. 点击工具栏扩展图标，扩展尝试自动读取并提交剪贴板中的 QQ 链接；读取受限时可以手动粘贴并点“开始保存”。
3. 第一次或会话过期时，在 QQ 网页播放器登录。若网页禁止自动播放，请点一次“播放”。
4. 需要转码时会打开本地处理页面，请保留到保存完成；成功后会自动关闭。
5. 重新打开扩展可查看结果、取消、重试或选择候选音频。最多 10 首串行处理。

默认保存到 Chrome 下载目录下的 `QQ音乐` 子目录。同名文件自动编号；同一浏览器会话内，完全相同的已保存链接不会重复处理。不同分享链接即使对应同一首，仍可能被视为不同任务。

## 选择保存文件夹

打开扩展 →“保存设置与使用帮助”→“选择保存文件夹…”。会进入独立设置页，在那里再次点击按钮，使用系统文件夹选择窗口选定位置并授权写入。独立设置页避免原生选择窗口弹出时扩展小弹窗自动关闭。

工具在本机 IndexedDB 中记住目录句柄。Chrome 可能在重启后要求重新授权：保存页会显示“授权并继续”，不会默默改存到其他位置。系统只提供目录名称，界面不会显示无法获取的绝对路径。

自定义目录模式直接写入目标文件夹，不经过 Chrome 下载列表；需要从你选择的目录查看文件。随时可以在设置页切回浏览器下载目录。正在保存时不能更改目录。

## 格式、状态和限制

- 原音频是 MP3 时保留原数据；其他受支持的普通音频经 Web Audio 解码，在本机 Worker 中编码为 192 kbps MP3。转码不会提高原音频音质。
- “已保存”只在 Chrome 下载完成或自定义目录写入关闭成功后显示。启动下载不算成功。
- 已知时长明显短于歌曲标注时暂停自动保存；无法检查时标注“完整性未验证”。时长相符不证明音质或内容完全相同。
- 捕获等待 90 秒、转换等待 5 分钟；超时、下载中断、授权失败可重试。转换上限为 80 MB、30 分钟、单/双声道。
- 仅处理当前网页可获取的普通音频，不处理加密容器、DRM 或 m3u8 分片合并。歌曲可用性受登录、账户权限、地区与平台策略影响。
- QQ 页面改版、音频域名变化或防盗链策略可能需要适配。
- 默认快捷键为 Mac `⌘⇧8` / 其他系统 `Ctrl+Shift+8`；本机未验证默认键生效，建议先用工具栏图标。如需全局快捷键，在 `chrome://extensions/shortcuts` 自行分配。
- 歌曲页与播放器保留以便登录、排错，完成后可关闭；不会清空原播放列表。

## 开发

需要 Node.js 22+、Python 3 和 FFmpeg/ffprobe；无需要 npm install 的运行时依赖，编码器已随扩展打包。

```sh
npm test
npm run check
npm run build
```

构建输出到 `dist/qq-music-helper-v0.3.0.zip`。构建仅收集扩展代码、README、隐私与第三方声明；不包含测试音乐、个人路径、账号、目录句柄或本地开发记录。
